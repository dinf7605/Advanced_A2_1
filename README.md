# 🎨 Brand Kit Generator — 브랜드 아이덴티티 생성기

브랜드 브리프(JSON)를 받아 **LLM으로 네이밍·슬로건·스토리·컬러 팔레트를 생성하고 →
이미지 생성 API로 로고 시안을 만들어 → 텍스트(JSON)와 이미지(PNG)로 저장하는** Python CLI 프로그램.

2026년 AI활용학습 **A2-1** 과제 · **5인 팀 프로젝트**

| 문서 | 내용 |
|------|------|
| [brand_kit_PRD.md](brand_kit_PRD.md) | 명세 — 스키마, 예외 정책, 역할 분담, 7일 계획 |
| [설명가이드.md](설명가이드.md) | 설계 근거 — 왜 이렇게 만들었는가, 데이터가 어떻게 흐르는가 |

## 실행

```bash
pip install -r requirements.txt
```

```bash
cp .env.example .env
```

`.env`에 키를 채운 뒤:

```bash
python main.py
```

**키 없이 먼저 돌려보려면** (네트워크를 타지 않습니다):

```bash
USE_MOCK=1 python main.py
```

실행하면 세 가지를 묻습니다. 두 번째·세 번째는 Enter로 넘길 수 있습니다.

```
브랜드 브리프 JSON 파일 경로를 입력하세요: briefs/sample_brief.json
결과를 저장할 폴더 (Enter=./output):
로고 시안 개수 (2~3, Enter=2): 3
```

| 9 | 실패해도 다음 단계 진행 | **예외 대신 반환값 계약** | [llm.py](brandkit/llm.py) |

## 설계 결정 (왜 이렇게 만들었는가)

### 1. 실패를 예외가 아니라 반환값으로 다룬다

| 대안 | 문제 |
|------|------|
| 호출부마다 `try/except` | 6번 반복해야 하고, **5명 중 누군가는 반드시 빠뜨립니다** |
| `except Exception: pass` | 내 오타(`NameError`)까지 "API 실패"로 둔갑해 원인을 못 찾습니다 |
| **계약으로 못 박기 ← 채택** | 모든 생성 함수가 **예외를 던지지 않고** `None` + `errors` 기록. `main()`에 `try`가 하나도 없습니다 |

요건 9("실패해도 다음 단계 계속 진행")를 개인의 주의력이 아니라 **구조로** 보장합니다.

### 2. LLM을 한 번에 몰아 받지 않고 단계별로 5번 호출한다

| | 1번에 몰아 받기 | **5번 나눠 호출 ← 채택** |
|---|---|---|
| 쿼터 | 1회 | 5회 |
| 슬로건 필드 하나가 깨지면 | **네이밍·스토리·컬러까지 전부 버림** | 슬로건만 `null` |
| 요건 9와의 관계 | **"다음 단계"가 애초에 없음** | 실패가 그 단계에 갇힘 |

쿼터 문제는 목업(§4)으로 풀었습니다. **요건과 충돌하는 구조를 최적화로 정당화하지 않습니다.**

### 3. 이미지 제공자를 어댑터로 뺐다

요건 7이 "DALL-E **등**"으로 열어두었고, 이미지 API는 **유료라 팀에서 막힐 수 있습니다.**
제공자마다 다른 것은 `credentials` / `build_request` / `call` / `extract_images` 네 개뿐이고,
타임아웃·재시도·오류 분기·로그는 공통 `generate_images()`에 한 번만 있습니다.
**제공자를 추가할 때 `generate_images()`를 고치지 마십시오.**

### 4. 목업에 "실패 모드"를 넣었다

실제 API로는 401을 마음대로 만들 수 없습니다.
**실패를 만들 수 없으면 요건 9를 만족했는지 증명할 수 없습니다.**

```bash
USE_MOCK=fail_naming python main.py
```

| 모드 | 재현하는 상황 |
|------|--------------|
| `1` | 전 단계 정상 |
| `fail_naming` | 네이밍만 실패 → 나머지 정상 **(요건 9 증명)** |
| `fail_llm` | LLM 전체 실패 → 로고와 저장만 진행 |
| `fail_image` | 이미지만 실패 → 텍스트·팔레트 정상 |
| `bad_hex` | LLM이 `"deep green"` 반환 → 기본 팔레트 대체 |

### 5. 개수 상한은 스키마가 아니라 후처리로 처리한다

요건은 네이밍 3~5개, 슬로건 3개입니다. 6개가 온 응답을 스키마 `maxItems`로 탈락시키면
재시도로 이어지고, 2회째도 6개면 섹션이 통째로 `null`이 됩니다. 그런데 **초과분은 잘라내면
요건을 충족합니다.** 반대로 부족은 어떤 후처리로도 만들 수 없습니다.

> **후처리로 고칠 수 있으면 고치고, 없으면 재시도.**
> 그래서 `minItems`만 검증에 맡기고 `maxItems`는 두지 않습니다.

### 6. 파싱과 검증을 분리했다

`json.loads`는 `{}` 도 통과시킵니다. 네이밍을 4개 요청했는데 0개가 온 응답도 문법적으로는
완벽한 JSON입니다. 그래서 **키·타입·개수를 따로 봅니다** (`llm.validate`).

같은 이유로 HEX도 스키마와 별개로 정규식 검증을 합니다 — `"deep green"`도 완벽한 문자열이라
스키마를 통과하지만, matplotlib에 넘기면 거기서 예외가 나 **PNG가 아예 안 만들어집니다.**

### 7. 파일이 생겼다고 이미지가 아니다

API가 오류를 JSON 본문으로 돌려줬는데 그대로 `.png`로 저장하면 파일은 생기지만 열리지 않습니다.
제출 직전에 발견하면 손 쓸 시간이 없습니다. 그래서 **저장 전에** PNG 매직 넘버(`\x89PNG`)와
크기를 확인하고, 아니면 저장하지 않습니다.

### 8. 로고 프롬프트에 `no text, no letters`를 넣었다

이미지 모델은 글자를 자주 뭉갭니다. 브랜드명을 그려달라고 하면 철자가 깨진 시안이 나옵니다.
**심볼 마크만 받고 글자는 나중에 얹는 것이 실무 방식이기도 합니다.**

또 2~3장을 같은 프롬프트로 뽑으면 비슷하게 나오므로, `symbol mark` / `abstract monogram` /
`emblem`처럼 **형식 키워드만 바꿔** 서로 다른 방향이 나오게 합니다.

### 9. 한글 폰트를 후보 목록으로 탐색한다

matplotlib 기본 폰트에는 한글 글리프가 없어 색 이름이 전부 `□□□`로 나옵니다.
그런데 **팀원 5명의 OS가 다릅니다.** Windows는 `Malgun Gothic`, macOS는 `AppleGothic`이
기본으로 있습니다. **한 사람의 PC에서만 되는 코드는 팀 프로젝트에서 버그와 같습니다.**

글자색은 배경 밝기로 자동 결정합니다 — `0.299R + 0.587G + 0.114B`.
균등 평균이 아닌 이유는 **사람 눈이 초록에 민감하고 파랑에 둔감**하기 때문입니다.
실제로 `#00FF00`은 검은 글자, `#0000FF`는 흰 글자가 선택됩니다.

### 10. 5명이 서로 기다리지 않게 했다

| 문제 | 대응 |
|------|------|
| 같은 파일을 5명이 고침 → 매번 충돌 | **파일 소유권** — 15개 모듈을 5명이 나눠 가짐 |
| LLM 코드가 나와야 나머지가 시작 | **인터페이스를 구현보다 먼저 확정** + 목업 |

혼자였으면 A1-1·A1-2처럼 단일 파일로 갔을 겁니다. **협업 자체가 설계에 흔적을 남깁니다.**

## API 키 관리

키는 **코드 어디에도 없습니다.** `.env`에서만 읽습니다.

| 환경변수 | 용도 | 없을 때 |
|----------|------|---------|
| `GEMINI_API_KEY` | LLM 5단계 | 안내 후 LLM 단계 전체 건너뜀 (계속 진행) |
| `IMAGE_PROVIDER` | `openai` \| `gemini` (기본 `openai`) | 기본값 사용 |
| `OPENAI_API_KEY` | `IMAGE_PROVIDER=openai`일 때 | 로고 단계만 건너뜀 |
| `USE_MOCK` | 목업 모드 | 실호출 |

> ⚠️ **한 번 커밋된 키는 파일에서 지워도 git 이력에 남습니다.**
> 실수로 커밋했다면 파일 수정이 아니라 **키 재발급**이 유일한 조치입니다.
